# Параллельное сканирование с воркерами

## Обзор

В новой версии DuplicateLink реализовано параллельное хеширование файлов с использованием пула воркеров. Это позволяет значительно ускорить процесс сканирования больших наборов файлов, особенно на многоядерных процессорах.

## Как это работает

### Двухэтапный процесс сканирования

#### Этап 1: Сбор списка файлов

На первом этапе программа выполняет рекурсивный обход файловой системы и собирает список всех файлов, подлежащих сканированию:

1. Обход всех каталогов, начиная с корневого
2. Применение правил из `.dupignore` (если файл существует)
3. Фильтрация скрытых файлов (если не включена опция `-include-hidden`)
4. Подсчет общего количества файлов
5. Отображение прогресса через progress-bar

**Результат**: Список файлов с информацией о пути и размере

#### Этап 2: Параллельное хеширование

На втором этапе программа использует пул воркеров для параллельного вычисления хешей:

1. Создается пул горутин (воркеров) заданного размера
2. Файлы распределяются между воркерами через канал
3. Каждый воркер:
   - Берет файл из канала
   - Вычисляет его хеш (SHA1 или MD5)
   - Сохраняет результат в потокобезопасную карту
   - Обновляет progress-bar
4. После обработки всех файлов воркеры завершают работу

**Результат**: Карта, где ключ - хеш, значение - список файлов с этим хешом

## Архитектура

### SafeHashMap

Потокобезопасная структура для хранения результатов хеширования:

```go
type SafeHashMap struct {
    mu   sync.Mutex                    // Мьютекс для блокировки
    data map[string][]models.FileHash  // Карта: хеш -> файлы
}
```

**Методы**:
- `NewSafeHashMap(capacity)` - создание с начальной емкостью
- `Add(hash, fileHash)` - потокобезопасное добавление файла
- `ToMap()` - получение обычной карты для дальнейшей работы

### fileJob

Структура для передачи информации о файле воркерам:

```go
type fileJob struct {
    path string  // Путь к файлу
    size int64   // Размер файла
}
```

## Использование

### Базовое использование (3 воркера по умолчанию)

```bash
./duplicatelink /path/to/folder
```

### Настройка количества воркеров

```bash
# 5 воркеров
./duplicatelink -workers 5 /path/to/folder

# 7 воркеров
./duplicatelink -workers 7 /path/to/folder

# 10 воркеров (максимум)
./duplicatelink -workers 10 /path/to/folder
```

### Рекомендации по выбору количества воркеров

| Количество файлов | Рекомендуемое количество воркеров |
|-------------------|-----------------------------------|
| < 1 000           | 3-5                               |
| 1 000 - 10 000    | 5-7                               |
| 10 000 - 100 000  | 7-10                              |
| > 100 000         | 10                                |

**Факторы, влияющие на выбор**:
- Количество ядер процессора (рекомендуется 1-2 воркера на ядро для снижения нагрузки на диск)
- Тип диска (SSD: до 10 воркеров, HDD: 3-5 воркеров)
- Средний размер файлов (маленькие файлы: больше воркеров)
- Доступная память

## Технические детали

### Потокобезопасность

Используются следующие механизмы синхронизации:

1. **sync.Mutex** - для защиты записи в карту хешей
2. **sync.WaitGroup** - для ожидания завершения всех воркеров
3. **Каналы Go** - для передачи задач воркерам

### Управление памятью

- Map инициализируется с емкостью = количество файлов
- Уменьшает количество реаллокаций
- Оптимизирует использование памяти

### Прогресс-бары

Используется библиотека `github.com/schollz/progressbar/v3`:
- Отдельный progress-bar для каждого этапа
- Реалтаймовое отображение прогресса
- Автоматическое завершение по окончании этапа
